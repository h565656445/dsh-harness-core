# 质量门禁

任务进入 Worker 前必须满足：

- TaskContract 通过 JSON Schema；
- 路由项目来自当前权威注册表；
- 必要输入、未知项和权限状态已明确；
- 受监督运动 Worker 至少有一份通过类型、大小、凭据扫描和 SHA-256 快照的材料；
- 内容审计只读 Worker 必须恰好各含一次 `content_audit + content_distribution + analyze`，不得混入其他项目域或动作；项目路径与当前机器注册表完全一致，五项机器门禁各出现一次且无冲突；
- 敏感副作用已经暂停。

任务完成前必须满足：

- 交付物存在且可定位；
- 对应项目自己的质量门禁通过；
- 验证结果与关键证据已记录；
- Worker 引用的材料哈希属于合同输入，不可变包复算一致，事实证据引文能在对应快照中逐字命中，且没有未核验主张、发布尝试或权威文件修改；
- 未执行未经批准的副作用；
- Loop 未超过两次执行和一次修正。

验证失败一次进入 `retrying`；第二次仍失败必须进入 `failed`，禁止无限循环或把失败包装成完成。

运动 Worker 的确定性门只能确认包完整性、材料哈希、逐字引文存在和结构约束；不能证明自然语言中的全部事实关系。结构通过后必须进入 `content_fact_review` 人工门，未复核前不得写 `completed`。

内容审计只读 Worker 可在确定性路径、哈希、Schema 和零副作用验证通过后完成“审查任务”；这不代表平台内容已获准发布，报价、服务承诺、账号和最终发布门禁保持不变。
其成片与封面还必须通过项目根及祖先路径、无符号链接/联接点、具体扩展名和对应文件头一致性检查；二进制证据与文件头从同一只读句柄取得，并在成功持久化前复检。回执仅声明 `verified`，合同和 Ledger 是 `completed` 的权威来源。
